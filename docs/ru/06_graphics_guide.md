# Графика

Данная глава описывает работу с графическим режимом ZX Sprinter: установку видеорежима, настройку палитры, рисование пикселей и двойную буферизацию.

## Установка видеорежима

Для переключения в графический режим используется `video_setmode`:

```c
#include <sprinter.h>

video_setmode(VMODE_320);   /* 320x256, 256 цветов */
```

Основные режимы:
- `VMODE_320` (0x81) -- 320x256, 256 цветов (8 бит/пиксель) -- наиболее распространённый
- `VMODE_320_16` (0x80) -- 320x256, 16 цветов
- `VMODE_640_16` (0x82) -- 640x256, 16 цветов
- `VMODE_TEXT80` (0x03) -- текстовый режим 80x32

## Настройка палитры

### Через BIOS #A4 (6-битные компоненты)

```c
bios_setpal(u8 index, u8 r, u8 g, u8 b);
```

Каждый компонент: 0-63 (6 бит). Палитра содержит 256 записей.

```c
/* Установить цвет 1 = ярко-красный */
bios_setpal(1, 63, 0, 0);

/* Установить цвет 2 = зелёный */
bios_setpal(2, 0, 63, 0);

/* Установить цвет 3 = синий */
bios_setpal(3, 0, 0, 63);
```

### Через BIOS #A6 (встроенная палитра GRAF)

Для быстрой настройки можно вызвать встроенную палитру GRAF через ассемблерную вставку:

```c
static void set_graf_palette(void) {
    __asm
        push    ix
        ld      b, #1
        ld      e, #0
        xor     a
        ld      c, #0xA6
        rst     #0x08
        pop     ix
    __endasm;
}
```

### Через video_setpal (8-битные компоненты)

```c
video_setpal(u8 index, u8 r, u8 g, u8 b);
```

Здесь каждый компонент: 0-255 (обычный диапазон).

### Диапазоны палитры

Для общей палитры графической подсистемы удобнее загружать сразу несколько цветов:

```c
static const video_rgb6_t palette[] = {
    {0, 0, 0},
    {63, 0, 0},
    {0, 63, 0},
    {0, 0, 63}
};

video_setpal_range(0, 4, palette);
video_setpal_graf();          /* встроенная палитра GRAF */
```

`video_setpal_range()` принимает аппаратные 6-битные компоненты (`0..63`), `video_setpal_range8()` принимает обычные 8-битные RGB-компоненты (`0..255`) и масштабирует их. Это API находится в основной `sprinter.lib`, поэтому им могут пользоваться и `gfx.lib`, и будущие подсистемы геометрических примитивов.

## Рисование пикселей

### Через bios_putpixel

```c
bios_putpixel(u16 x, u8 y, u8 color);
```

Рисует один пиксель:
- `x`: 0-319 (в режиме 320x256)
- `y`: 0-255
- `color`: индекс цвета в палитре

```c
/* Красная точка в центре экрана */
bios_putpixel(160, 128, 1);
```

### Рисование линий и фигур

SDK не предоставляет высокоуровневых графических примитивов. Линии, прямоугольники и другие фигуры рисуются попиксельно:

```c
/* Горизонтальная линия */
void hline(u16 x1, u16 x2, u8 y, u8 color) {
    u16 x;
    for (x = x1; x <= x2; x++)
        bios_putpixel(x, y, color);
}

/* Вертикальная линия */
void vline(u16 x, u8 y1, u8 y2, u8 color) {
    u8 y;
    for (y = y1; y <= y2; y++)
        bios_putpixel(x, y, color);
}

/* Рамка */
void rect(u16 x1, u8 y1, u16 x2, u8 y2, u8 color) {
    hline(x1, x2, y1, color);
    hline(x1, x2, y2, color);
    vline(x1, y1, y2, color);
    vline(x2, y1, y2, color);
}
```

## ОБЯЗАТЕЛЬНО: video_safe_porty()

После завершения рисования пикселей **необходимо** вызвать:

```c
video_safe_porty();
```

Функция `bios_putpixel` использует аппаратный регистр PORT_Y для выбора строки VRAM. Если не сбросить PORT_Y в безопасное значение (0xC0), последующие обращения к памяти (загрузка кода, чтение данных, операции со стеком) могут случайно попасть в область VRAM и повредить изображение.

**Типичная ошибка:**
```c
/* НЕПРАВИЛЬНО -- забыли video_safe_porty() */
video_setmode(VMODE_320);
for (x = 0; x < 320; x++)
    bios_putpixel(x, 128, 255);
dss_waitkey();               /* <-- может повредить VRAM! */
video_setmode(VMODE_TEXT80);
```

**Правильно:**
```c
video_setmode(VMODE_320);
for (x = 0; x < 320; x++)
    bios_putpixel(x, 128, 255);
video_safe_porty();          /* <-- сбрасываем PORT_Y */
dss_waitkey();
video_setmode(VMODE_TEXT80);
```

## Структура VRAM

Видеопамять организована линейно:
- Каждая строка экрана занимает **1 КБ** (1024 байта) в VRAM, хотя используются только первые 320 байт (по 1 байту на пиксель в режиме 320x256)
- Строка выбирается через регистр **PORT_Y** (порт 0x89)
- Запись пикселей производится непосредственно в VRAM через окно памяти WIN3

Для прямого доступа к VRAM (без `bios_putpixel`):

```c
/* Подключить VRAM-страницу к окну памяти */
video_mapvram(3, 0x50);   /* WIN3 = VRAM страница 0 */

/* Прямая запись пикселя */
/* Адрес = 0xC000 + x (для первой строки) */
```

> **Примечание:** прямой доступ к VRAM сложнее в реализации, но значительно быстрее, чем `bios_putpixel`.

## Двойная буферизация

Для плавной анимации используйте двойную буферизацию:

```c
/* Рисуем в невидимый буфер */
/* ... bios_putpixel(...) ... */

video_safe_porty();

/* Ждём вертикальную синхронизацию */
video_vsync();

/* Переключаем буферы */
video_swap();
```

Функция `video_swap()` переключает отображаемый буфер через бит 0 регистра RGMOD (`#C9`). Пока один буфер отображается, программа рисует в другой, и наоборот. `video_vsync()` использует аппаратный sync-бит Sprinter `#FFFE.5`, поэтому анимационные примеры должны вызывать его непосредственно перед `gfx_flip()`/`video_swap()`. Статическим примерам синхронизация на каждом кадре не нужна, если они не переключают видимые страницы.

## Опциональная библиотека gfx.lib

Для спрайтов, копирования экранов и восстановления фона используется отдельный архив `build/gfx.lib`. Он не добавляется в программу автоматически и не увеличивает размер EXE, если не используется:

```make
EXTRA_LIBS = $(SDK_DIR)build/gfx.lib
```

Библиотека работает только в режиме `VMODE_320` и использует общую палитру, задаваемую через `video_setpal*()`.

```c
#include <sprinter/gfx.h>

gfx_draw_sprite8(GFX_SCREEN_0, 40, 40, sprite8, GFX_MASKED);
gfx_draw_sprite16(GFX_SCREEN_0, 80, 40, sprite16, GFX_OPAQUE);
gfx_draw_sprite24(GFX_SCREEN_1, 120, 40, sprite24, GFX_MASKED);

gfx_restore_sprite16(GFX_SCREEN_0, 80, 40);
gfx_copy_screen(GFX_SCREEN_1, GFX_SCREEN_0);
gfx_blit_rect(GFX_SCREEN_0, 32, 40, GFX_SCREEN_0, 32, 48, 128, 64);
gfx_flip();
```

Доступны фиксированные размеры спрайтов 8x8, 16x16 и 24x24. Цвет `0xFF` считается прозрачным при флаге `GFX_MASKED`. Спрайты 16x16 и 24x24, копирование прямоугольников и восстановление фона используют аппаратный акселератор.

Восстановление работает копированием из DRAM-зеркала того же экрана обратно в VRAM. Если нужно временно нарисовать объект без изменения сохранённого фона, используйте `GFX_VRAM_ONLY`, а затем `gfx_restore_rect()` или один из `gfx_restore_sprite*()`. `gfx_copy_rect()` копирует между экранами в тех же координатах; `gfx_blit_rect()` копирует между произвольными координатами источника и назначения и подходит для ускоренного скроллинга.

### Графические примитивы

`gfx.lib` также предоставляет простые примитивы, использующие ту же палитру и те же аргументы экрана:

```c
gfx_draw_pixel(GFX_SCREEN_0, 10, 20, 15, GFX_OPAQUE);
gfx_draw_line(GFX_SCREEN_0, 20, 30, 160, 90, 8, GFX_OPAQUE);
gfx_draw_line_thick(GFX_SCREEN_0, 20, 100, 220, 40, 3, 4, GFX_OPAQUE);
gfx_draw_rect(GFX_SCREEN_0, 12, 18, 296, 220, 15, GFX_OPAQUE);
gfx_draw_rect_thick(GFX_SCREEN_0, 24, 32, 80, 40, 2, 10, GFX_OPAQUE);
gfx_fill_rect(GFX_SCREEN_0, 20, 204, 80, 22, 1, GFX_OPAQUE);
gfx_draw_circle(GFX_SCREEN_0, 260, 190, 24, 14, GFX_OPAQUE);
```

Линии отсекаются по экрану 320x256. `gfx_draw_line_thick()` использует квадратную кисть заданной толщины, поэтому толстые диагонали выглядят как ступенчатая полоса. `gfx_fill_rect()` и `gfx_draw_vline()` трактуют `height == 0` как 256 строк, что удобно для полноэкранных операций. Используйте `GFX_VRAM_ONLY` для временных примитивов, которые потом нужно убрать восстановлением из DRAM-зеркала.

Пример `20_gfxst` демонстрирует слой примитивов вместе со спрайтами: белую рамку экрана, красный залитый прямоугольник, тонкую серую линию, толстую синюю диагональ, белую окружность и четыре X/cross-спрайта.

## PNG-ресурсы

Графику можно хранить как C-массивы или подготовить из PNG до сборки:

```bash
python3 tools/png2gfx.py \
    --out gfxdemo.gfx \
    --header res.h \
    --name demo_gfx \
    assets/sprite16.png assets/sprite24.png
```

Утилита принимает неинтерлейсные 8-битные RGB/RGBA/indexed PNG, строит общую палитру до 255 непрозрачных цветов, использует `0xFF` как прозрачный пиксель и пишет page-friendly `.gfx`, где данные ресурса не пересекают границу 16 КБ. Сгенерированный заголовок содержит `video_rgb6_t *_palette[]` и `gfx_resource_t *_resources[]`.

## BMP-ресурсы

Для 8-битных indexed BMP используется `tools/bmp2gfx.py`. Он поддерживает
полноэкранные изображения через `--image` и sprite sheet через `--sheet PATH:WxH`:

```bash
python3 tools/bmp2gfx.py \
    --out ppong.gfx \
    --header res.h \
    --name ppong \
    --image assets/bg0.bmp \
    --image assets/bg1.bmp \
    --sheet assets/sprites.bmp:16x16 \
    --sheet-transparent-index 255
```

Если `--palette` не указан, утилита строит одну общую палитру по всем входным
изображениям и sheet-тайлам. Прозрачный индекс sheet-файла не включается в
палитру. Максимум — 255 непрозрачных цветов; при превышении лимита сборка
останавливается с ошибкой `combined palette exceeds 255 colors`.

Для старых сценариев можно передать `--palette file.bmp`: тогда палитра берётся
из указанного BMP, а остальные изображения ремапятся к ближайшим цветам этой
палитры. Это используется, когда нужна заранее фиксированная палитра.

Во время выполнения файл загружается в страничную память, а при выводе передаются номер базовой страницы и индекс ресурса:

```c
page = dss_getmem();
gfx_load_resource_pages("GFXDEMO.GFX", page, 1);
video_setpal_range(0, DEMO_GFX_PALETTE_COUNT, demo_gfx_palette);
gfx_draw_resource(GFX_SCREEN_0, 96, 80, page, demo_gfx_resources, 0, 0);
```

Для runtime-ресурсов используйте только имена 8.3. DSS не открывает long filenames, поэтому сгенерированные файлы вроде `GFXDEMO.GFX` и заголовки вроде `res.h` намеренно имеют короткие имена.

## Возврат в текстовый режим

После завершения работы с графикой верните текстовый режим:

```c
video_setmode(VMODE_TEXT80);
```

Если этого не сделать, DSS попытается выводить текст в графическом режиме, что приведёт к нечитаемому выводу.

## Полный пример

```c
#include <sprinter.h>

/* Встроенная палитра GRAF через BIOS #A6 */
static void set_graf_palette(void) {
    __asm
        push    ix
        ld      b, #1
        ld      e, #0
        xor     a
        ld      c, #0xA6
        rst     #0x08
        pop     ix
    __endasm;
}

void main(void) {
    u8 y, c;
    u16 x;

    /* Переключение в графику */
    video_setmode(VMODE_320);
    set_graf_palette();

    /* Палитра: 16 полос по 20px */
    for (c = 0; c < 16; c++) {
        for (y = 4; y < 20; y++) {
            for (x = (u16)c * 20; x < (u16)c * 20 + 20; x++) {
                bios_putpixel(x, y, c * 16 + 8);
            }
        }
    }

    /* Белая рамка */
    for (x = 0; x < 320; x++) {
        bios_putpixel(x, 28, 255);
        bios_putpixel(x, 240, 255);
    }
    for (y = 28; y < 241; y++) {
        bios_putpixel(0, y, 255);
        bios_putpixel(319, y, 255);
    }

    /* Диагональный градиент */
    for (y = 30; y < 240; y++) {
        for (x = 2; x < 318; x++) {
            bios_putpixel(x, y, (u8)((x + (u16)y) & 255));
        }
    }

    /* ОБЯЗАТЕЛЬНО: сбросить PORT_Y! */
    video_safe_porty();

    /* Ждём клавишу */
    dss_waitkey();

    /* Возврат в текстовый режим */
    video_setmode(VMODE_TEXT80);
}
```
